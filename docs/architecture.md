# Arena architecture

The browser downloads a static TypeScript application, `public/arena/san-jose-block.json`, and bundled Poly Haven and project-generated texture files for the default arena. The full source extract remains available for supported custom arena URLs. It makes no map or texture API requests while players explore the arena.

`src/world/arena.ts` defines the arena data format, center and bounds validation, coordinate conversion, and elevation interpolation. The 140 m playable block is centered over the denser streets, with a 65 m surrounding visual buffer. `scripts/build-block.mjs` derives that compact asset from the full 700 m extract.

`src/world/mapViewer.ts` turns the data into ground, roads, curbs, crosswalks, parks, moving trees, buildings, a visible boundary, and a bundled daylight HDR sky. It groups buildings and roads by spatial cell for view culling. `src/world/surfaceTextures.ts` loads bundled PBR photo materials, storefronts, and foliage cutouts; `src/world/scenery.ts` adds windows, ledges, doors, storefronts, awnings, facade trim, streetlights, manholes, drains, planters, hydrants, and a fallback sky gradient. Three.js `WebGPURenderer` selects WebGPU when available and WebGL 2 otherwise. Both paths use dynamic shadows and normal maps. Render resolution adapts to sustained frame rates.

`src/world/collision.ts` derives deterministic obstacle locations and clear street spawns from the arena data. `src/world/physics.ts` builds Rapier 3D colliders for terrain, building walls, trees, furniture, cover, and the arena edge. The player is a kinematic capsule updated at a fixed 60 Hz; Rapier's character controller handles sliding, grounding, low steps, and crouch clearance. `src/world/cover.ts` instantiates bundled CC0 concrete barrier models at the same cover locations. `src/game/playerController.ts` applies acceleration, gravity, jump buffering, brief coyote time, running, crouching, and camera look. `src/game/playerHands.ts` animates gloved hands attached to the camera. `src/main.ts` opens the controls modal and pauses the player while it is visible.

The renderer boundary is a `MapViewer` interface with `setArena` and `destroy`, plus player pose, remote avatar, weapon display, and static shot-ray methods. Combat uses Rapier's 3D raycasts to test static obstruction and the separate deterministic collision layer for pickup placement. `src/game/matchState.ts` holds health, inventory, and respawns; `src/network/peerRoom.ts` carries combat intents and snapshots. Data generation remains separate in `scripts/build-arena.mjs`; players never query the source services. See [multiplayer architecture](multiplayer.md) for the room protocol.

The handoff's Google Photorealistic 3D Tiles path is no longer used in this phase. The free-data pilot establishes real-world layout and a working browser renderer. Fully authored photorealistic facades, rigged character animation, arbitrary location selection, dynamic props, and stronger multiplayer authority remain future work. See [rendering notes](rendering.md) for current measurements and technical decisions.
