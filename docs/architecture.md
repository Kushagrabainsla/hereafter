# Phase 1 architecture

The browser downloads a static TypeScript application, `public/arena/san-jose.json`, and bundled CC0 texture files. It makes no map or texture API requests while players explore the arena.

`src/world/arena.ts` defines the arena data format, center and bounds validation, coordinate conversion, and elevation interpolation. The 240 m playable block is centered over the denser streets while the larger source extract keeps surrounding buildings visible. `src/world/mapViewer.ts` turns that data into ground, roads, curbs, crosswalks, parks, moving trees, buildings, and a visible arena boundary. `src/world/surfaceTextures.ts` loads bundled PBR photo materials and foliage cutouts; `src/world/scenery.ts` adds windows, ledges, doors, awnings, streetlights, manholes, drains, planters, hydrants, and a sky gradient. Three.js `WebGPURenderer` selects WebGPU when available and WebGL 2 otherwise. Both paths use dynamic shadows and normal maps. `src/world/collision.ts` derives simple building, tree, street furniture, and arena colliders from the same data and finds a clear street spawn. `src/game/playerController.ts` handles first-person walking, running, jumping, crouching, and trackpad or mouse look. `src/game/playerHands.ts` animates hands attached to the camera. `src/main.ts` opens the controls modal and pauses the player while it is visible.

The renderer boundary is a `MapViewer` interface with `setArena` and `destroy`. The separate collision layer is an initial gameplay approximation based on map footprints; a later authoritative simulation can use it without treating the visual mesh as gameplay truth. Data generation remains separate in `scripts/build-arena.mjs`; players never query the source services.

The handoff's Google Photorealistic 3D Tiles path is no longer used in this phase. The free-data pilot establishes real-world layout and a working browser renderer. Photorealistic detail, arbitrary location selection, detailed physics, and multiplayer are separate future tasks.
