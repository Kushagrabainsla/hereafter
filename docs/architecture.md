# Arena architecture

The browser downloads a static TypeScript application, `public/arena/san-jose-block.json`, and bundled Poly Haven and project-generated texture files for the default arena. The full source extract remains available for supported custom arena URLs. It makes no map or texture API requests while players explore the arena.

`src/world/arena.ts` defines the arena data format, center and bounds validation, coordinate conversion, and elevation interpolation. The 140 m playable block is centered over the denser streets, with a 65 m surrounding visual buffer. `scripts/build-block.mjs` derives that compact asset from the full 700 m extract.

`src/world/mapViewer.ts` turns the data into ground, roads, curbs, crosswalks, parks, moving trees, buildings, a visible boundary, and a bundled daylight HDR sky. It groups buildings and roads by spatial cell for view culling. `src/world/surfaceTextures.ts` loads bundled PBR photo materials, storefronts, and foliage cutouts; `src/world/scenery.ts` adds windows, ledges, doors, storefronts, awnings, facade trim, streetlights, manholes, drains, planters, hydrants, and a fallback sky gradient. Three.js `WebGPURenderer` selects WebGPU when available and WebGL 2 otherwise. Both paths use dynamic shadows and normal maps. Render resolution adapts to sustained frame rates.

`src/world/collision.ts` derives building, tree, street furniture, concrete cover, and arena colliders from the same data and finds a clear street spawn. `src/world/cover.ts` instantiates bundled CC0 concrete barrier models at those same cover locations. `src/game/playerController.ts` handles first-person walking, running, jumping, crouching, and trackpad or mouse look. `src/game/playerHands.ts` animates gloved hands attached to the camera. `src/main.ts` opens the controls modal and pauses the player while it is visible.

The renderer boundary is a `MapViewer` interface with `setArena` and `destroy`, plus player pose, remote avatar, and weapon display methods. The separate collision layer is an initial gameplay approximation based on map footprints. Combat uses that layer for cover checks and pickup placement, without treating the visual mesh as gameplay truth. `src/game/matchState.ts` holds health, inventory, and respawns; `src/network/peerRoom.ts` carries combat intents and snapshots. Data generation remains separate in `scripts/build-arena.mjs`; players never query the source services. See [multiplayer architecture](multiplayer.md) for the room protocol.

The handoff's Google Photorealistic 3D Tiles path is no longer used in this phase. The free-data pilot establishes real-world layout and a working browser renderer. Fully authored photorealistic facades, rigged character animation, arbitrary location selection, and detailed physics remain future work. See [rendering notes](rendering.md) for current measurements and technical decisions.
