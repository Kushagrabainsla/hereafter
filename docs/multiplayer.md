# Multiplayer architecture

The playable network slice uses invite-based rooms. `src/network/peerRoom.ts` opens a Trystero room using a 10-character random room code. Trystero's default public Nostr relays exchange connection information; gameplay packets travel between browsers over WebRTC data channels. GitHub Pages serves only static files. There is no project-operated room server or per-session map request.

Each browser renders the arena locally. `src/game/playerController.ts` supplies its local pose at up to 20 updates per second. The versioned `pose-v1` action includes an arena key, sequence number, location, view, jump height, and movement flags. Receivers reject out-of-order, malformed, wrong-arena, out-of-bounds, or implausibly large position changes. An accepted respawn resets the position check. `src/game/remotePlayers.ts` interpolates remote avatars between updates. Each peer computes a spawn slot from the sorted connected peer IDs so newly joined players do not occupy the same point. The room link includes the current arena URL parameters.

`src/game/combatRules.ts` defines the starting knife, pistol and carbine, deterministic pickup positions, weapon range and damage. Rapier 3D raycasts reject shots blocked by terrain, buildings, or cover. `src/game/matchState.ts` owns health, inventory, ammo, reloads, kills, deaths, respawns, and 30-second pickup returns. It ignores stale player poses for attacks and pickups. The lowest connected peer ID temporarily coordinates combat. Other peers send attack and pickup intents; the coordinator checks range, cover, ammo, cooldown, and proximity before broadcasting a versioned combat snapshot. Peers retain the latest snapshot so another can take over when the coordinator leaves. `src/game/weaponVisuals.ts` renders held weapons and street pickups.

This is a prototype authority model. Positions still come from clients, so a modified client could move illegally despite the distance and bounds checks. Full input-based movement validation, correction, and lag compensation need a stronger authority protocol. The coordinator is chosen deterministically but has no heartbeat or epoch-based handoff yet; contested joins and abrupt disconnects need more testing. A connection may also need a TURN relay when direct WebRTC cannot cross a particular network; the public signaling relays do not supply that relay. Their availability is outside this project's control, so production matchmaking needs a monitored signaling and TURN plan.

### Combat feedback and hit zones

Combat protocol v2 isolates rooms from older clients. Attack intents carry the aim angles captured when the trigger is pressed; the leader uses its most recent accepted position and stance. The leader resolves oriented head, torso and leg volumes, static Rapier obstruction, range, cooldown, reload, ammo and health. Headshots multiply damage by 2.5, leg hits by 0.7; firearms lose up to 45% damage toward maximum range. These are gameplay tuning values, not wound simulation. Confirmed damage is capped at remaining health.

Every accepted attack emits a replicated event, including misses, with its ray and stopping distance. Clients display a short tracer, impact puff, confirmed damage and elimination feedback. Effects are bounded to 48 active groups and share geometry. Holding fire in pointer lock repeats the carbine; pistol fire remains semi-automatic. Sprinting prevents attacks. Camera recoil changes subsequent aim.

Shots remain hitscan: the trail is feedback, not a simulated bullet with travel time or drop. Players use approximate anatomical volumes rather than per-bone collision; remote interpolation, network latency and leader trust still limit competitive accuracy. There is no lag compensation or penetration. The existing infinite reserve ammunition remains. The authored view-model loader is ready, but realistic arms, weapons and characters still need suitable licensed art.
