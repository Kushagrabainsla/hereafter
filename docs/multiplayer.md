# Multiplayer architecture

The first playable network slice is invite-based shared presence. `src/network/peerRoom.ts` opens a Trystero room using a 10-character random room code. Trystero's default public Nostr relays exchange connection information; gameplay packets travel between browsers over WebRTC data channels. GitHub Pages serves only static files. There is no project-operated room server or per-session map request.

Each browser renders the arena locally. `src/game/playerController.ts` supplies its local pose at up to 10 updates per second. The versioned `pose-v1` action includes an arena key, sequence number, location, view, jump height, and movement flags. Receivers reject out-of-order, malformed, or wrong-arena packets. `src/game/remotePlayers.ts` interpolates remote avatars between updates. Each peer computes a spawn slot from the sorted connected peer IDs so newly joined players do not occupy the same point. The room link includes the current arena URL parameters.

This implementation assumes honest peers. Packet bounds checks prevent bad data from breaking rendering, but do not prove a movement was legal. For competitive play, the next step is an elected match authority that checks movement and resolves shots, damage, health, and respawns. Add authority epochs, heartbeats, and migration after two-player combat works. A connection may also need a TURN relay when direct WebRTC cannot cross a particular network; the public signaling relays do not supply that relay. Their availability is outside this project's control, so production matchmaking needs a monitored signaling and TURN plan.
